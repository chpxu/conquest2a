File I/O

Coordinate file conversion to and from the CONQUEST coordinate file is handled by the io.write_coords and io.read_coords

Example usage

First, define conquest_species, e.g.

from conquest2a.conquest import conquest_species, conquest_coordinates

cs = conquest_species({1:"K", 2: "Cu", 3: "Cu", 4: "F"})

Then, assuming you have a completely filled out conquest_coordinates instance, you can just write immediately:

from conquest2a.io import write_coords
cq = write_coords("dest_file.cell", cs, format="cell")

Check the API below. Writing supports cell, vasp (POSCAR), xsf (including additional vector quantities), ext/xyz as well as writing out a CONQUEST coordinates file (default extension is .dat).

If you instead want to _read_ in a coordinate file,

from conquest2a.io import read_coords
cq = read_coords("read_file.cell", cs, format="cell")
coords = cq.coords # Now you can use this to do whatever

This will now expose a conquest_coordinates instance for you to use. Currently supports reading CONQUEST files, cell and POSCAR .vasp files.

API

class conquest2a.io.read_coords(path: str, species: conquest_species, format: Literal['vasp', 'cell', 'cq'] | None = None, encoding: str = 'utf-8', cq_units: Literal['bohr', 'ang'] = 'bohr')

Class to read external coordinates data and store them in a conquest_coordinates instance.

Parameters:

  • path (str) – Path to file to read

  • species (conquest_species) – conquest_species instance

  • format (Literal["vasp", "cell"] | None, optional) – File format, defaults to None in which case it will infer from the file extension of path

  • encoding (str, optional) – File encoding, defaults to “utf-8”

  • cq_units (Literal["bohr", "ang"], optional) – Units to use in conquest_coordinates, defaults to “bohr”. vasp is assumed to be read entirely in angstroms.

read() → None

Wrapper function to read file based off self.format. :raises ValueError: If self.format is unsupported.

read_cell() → None

Parse a CASTEP cell file completely and fill out a conquest_coordinate instance

Raises:

  • KeyError – If neither lattice_cart nor lattice_abc are in the cell file

  • KeyError – If neither position_cart nor position_abs are in the cell file

read_conquest() → None

This method reads a CONQUEST coordinate file.

CONQUEST coords file split into 3 main chunks:

  • first 3 lines are lattice vectors

  • fourth line is the total number of atoms in the unit cell

  • the following lines describe each atom and look like

    <double> <double> <double> <int> <char> <char> <char>

read_poscar() → None

Method which reads a POSCAR file extracting only what is needed to make a CONQUEST coordinates instance

Raises:

  • ValueError – If the number of scaling factors is incorrect

  • NotImplementedError – Negative scale factors

class conquest2a.io.write_coords(dest: str, cq_coords: conquest_coordinates, format: Literal['cq', 'vasp', 'cell', 'xyz', 'extxyz', 'xsf'], precision: int = 10, mode: str = 'w', encoding: str = 'utf-8', convert_to: Literal['bohr', 'ang'] | None = None, comment_line: str = '', time: float = 0.0, write_spin: bool = False, write_force: bool = False)

Class to convert data held in a conquest_coordinates instance into various coordinate file formats: xsf, cell, vasp, xyz and extxyz.

Parameters:

  • dest (str) – Path to output file.

  • cq_coords (conquest_coordinates) – conquest_coordinates instance with data

  • format (Literal["cq","vasp","cell","xyz","extxyz", "xsf"]) – Type of coordinate file to write

  • precision (int, optional) – Number of decimal places, defaults to 10

  • mode (str, optional) – File IO mode, defaults to “w”

  • encoding (str, optional) – File encoding, defaults to “utf-8”

  • convert_to (Literal["bohr", "ang"] | None, optional) – Whether to convert lattice parameters and cartesian coordinates to specified units, defaults to None (data is preserved as-is)

  • comment_line (str, optional) – What unit factor to target, defaults to None (content written as-is)

  • time (float, optional) – Animation time (extxyz only), defaults to 0.0

  • write_spin (bool, optional) – Whether to write out atom.spins (XSF only, mutually exclusive with write_force), defaults to False

  • write_force (bool, optional) – Whether to write out atom.force (XSF only, mutually exclusive with write_spin), defaults to False

Raises:

ValueError – If write_force and write_spin are True, error out.

create_atoms_str() → tuple[str, str]

Creates a line for an atom, for the XYZ file.

Returns:

Components of the line to write: the element and the numbers

Return type:

tuple[str, str]

write() → None

Wrapper function to write file based off self.format. :raises ValueError: If self.format is unsupported.

write_conquest() → None

Method to write a CONQUEST coordinates file given a conquest_coordinates instance.

write_extxyz() → None

Method to write a .extxyz for a basic XYZ file given a conquest_coordinates instance.

The main advantage of .extxyz is the ability to specify columns and the time, which is very useful for animations. I recommend just using CONQUEST’s ability to output .extxyz files at different timesteps however.

write_vasp() → None

Method to write a basic VASP POSCAR file given a conquest_coordinates instance.

Parameters:

  • dest (str) – Path to write the new coordinates file.

  • data (conquest_coordinates) – conquest.conquest_coordinates instance to write.

  • encoding (str, optional) – File encoding, defaults to “utf-8”

  • is_angstrom (bool, optional) – Whether the data in conquest_coordinates is already in angstroms instead of Bohrs, defaults to False.

write_xsf() → None

Method to write an XSF file optionally with a vector attached to each atom

write_xyz() → None

Method to write a .xyz for a basic XYZ file given a conquest_coordinates instance.
